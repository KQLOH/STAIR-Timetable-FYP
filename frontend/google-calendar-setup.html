OPTIONAL GOOGLE CONNECTION

Connect your test calendar

STAIR already has a local sandbox. These steps enable a separate Google test calendar. Connecting does not approve or send any classes.

  1. Create a Google Cloud project and enable Calendar API. Open the Google Cloud console. Select your project, open APIs & Services → Library, find Google Calendar API and enable it.
  2. Configure Google Auth Platform. Set your application name and contact details. For a personal Gmail account choose an External audience, keep the app in Testing, and add your own Google account as a test user. Follow your institution's restrictions if using a university account.
  3. Create a Web application OAuth client. In Clients, choose Web application. Add this exact Authorized redirect URI:
    STAIR_CALLBACK_URL
    Use the address above, including the port and callback path. A Desktop app client is not used by this STAIR host.
  4. Download the client JSON privately. Keep it outside the project folder, for example in Downloads. Do not paste its Client Secret into STAIR, chat, GitHub or screenshots.
  5. Create a separate Google calendar. In Google Calendar, choose Other calendars → + → Create new calendar. Name it “STAIR FYP Test”. Open its Settings → Integrate calendar and copy its Calendar ID. Use this test calendar, not your primary calendar.
  6. Check configuration without connecting. Stop your previous STAIR server in its own window. From the project folder, replace the example file path and calendar ID below:
    .venv/Scripts/python.exe -B tools/run_student_app.py --google-credentials "C:/Users/Asus/Downloads/your-client.json" --google-calendar-id "your-test-calendar-id" --check-google-config
    This only reads local configuration. It does not contact Google or print secrets.
  7. Start STAIR with the same configuration. Remove --check-google-config and add --open-browser. Sign in to STAIR, open Review & output, choose Connect Google Calendar and personally complete Google's authorization.
  8. Preview before sending classes. Select your classes and dates, select the connected Google destination, then preview. Check the displayed target and changes, approve the preview and apply it. Open Google Calendar to inspect the result. If an outcome is uncertain, use Check saved result; do not repeatedly apply it.
Troubleshooting
  • redirect_uri_mismatch: compare the complete callback URI above with the Web client's Authorized redirect URIs. A different STAIR port needs its own exact callback entry.
  • Access blocked / app in testing: verify that the Google account is on your app's test-user list and that your organization permits the requested access.
  • Wrong calendar or read-only access: use a dedicated secondary calendar where you have owner or writer permission. STAIR checks this after authorization.
  • Strict FYP mode: registered-accept mode intentionally uses the local sandbox. Google is a separately configured personal application extension.
  • After restarting: connect Google again. OAuth tokens remain in server memory and are not saved to the repository.

Standard Calendar API use currently has no additional charge within Google's stated limits; cloud hosting and AI analysis are separate services. See Google's current limits and pricing.
