## Implemented

The account launcher now serves the existing frontend and API together. Students can create a local STAIR account, sign in, upload/paste their own timetable, edit through the existing evidence/revision workflow, reopen saved timetables and reconnect editing without console authorization commands. Accounts and review stores are isolated; encrypted journals persist records while login and external-service credentials remain temporary.

The calendar page supports explicit one-time/weekly dates, bounded date ranges, timezone confirmation, excluded dates and source notes. It checks saved class revisions, proven hard failures, times, weekdays, DST, overlapping selections and clashes with previously saved STAIR occurrences. Preview, approval and application are distinct operations. Source/schedule revisions, session changes, expiry and target changes invalidate pending authority. The local application calendar persists actual occurrences; repeat applications return their recorded outcome. No event deletion is implemented.

Optional Google code implements state/PKCE OAuth, a server-configured secondary test target, target permission checks, deterministic event IDs, conditional updates, intent-before-submit and read-only recovery checks. Google is disabled until privately configured. No real Google authorization or calendar write was performed.

JSON export retains original predictions, current revisions, evidence, routing and personal schedule confirmations separately. Reference import produces descriptive differences without promoting a reference to independent Gold. A personal completeness checklist is available alongside the existing analysis. Neither it nor account creation establishes independent verification.

The existing S2b assessment endpoint now accepts a bounded full evidence envelope of up to 8 MiB, matching review ingestion; compact digest envelopes remain the frontend preference. This fixes the observed full-envelope synthetic OCR regression without changing baseline algorithms or decision rules.
